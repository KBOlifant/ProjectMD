4 · The pipeline

Scanner:Mode chooses: static = mock (the default in appsettings.json!), extract = Playwright, no AI, ai = Playwright + Groq. The free stage always runs first; if it fails, Groq is never called. Each AI step may fail without failing the scan.

Code writes the facts

Tech stack, API endpoints, colours, fonts, outline, measured animations. Never invented by the AI.

Groq writes the prose

Overview, architecture bullets, endpoint purposes, tips, animation descriptions, design breakdown.

Two outputs

Markdown (the .md text) and Analysis (JSON for the Design, Components and Animations tabs).

5 · Where Playwright comes in

Only in the backend (Microsoft.Playwright 1.63 for .NET). One shared headless Chromium; each scan gets a fresh, throw-away context. The browser itself is not allowed to look up any host name: every request is handed to our proxy, checked, and fetched by our own HTTP client.

Why so careful? Playwright's own interception misses redirect hops, so a public site that redirects to 169.254.169.254 (cloud metadata) could reach your server's internals. This design blocks that (SSRF protection). Also: frontend/lib/scrape.ts uses Playwright too, but it is not wired into the app, the package is not installed, and it has no such guard.

6 · Screenshots: taken, stitched, read

VisualCapturer scrolls with real mouse-wheel events (so smooth-scroll libraries react), waits 700 ms, and shoots only the visible 1440×900 window as a JPEG at quality 60. Six frames, 760 px apart.

↓ ContactSheet.BuildHtml: our own HTML page, frames as data: images, 3 × 2 grid, numbered captions ↓
rendered in a second context with JavaScript OFF, then one full-page screenshot ↓
↓ MotionPromptBuilder.PickImages (max 3) → GroqLlmClient.BuildBody ↓
part 1 · text

The measured facts between <<<VISUAL and VISUAL>>>: libraries, animations with real timings, colours, fonts.

part 2 · image_url

data:image/jpeg;base64,… the first screen, full size.

part 3 · image_url

The contact sheet. The model compares numbered frames to spot what moved.

Screenshots live in memory for that one scan only. They are never written to disk or the database. Each image is budgeted at 2048 tokens before the call.

8 · The database

PostgreSQL on Aiven through EF Core. Firebase only knows your login; everything else is here. Clearing history is a soft delete (DeletedAt), so cleared scans still count toward the month.

9 · RBAC: who may do what

The matrix exists twice: Auth/Permissions.cs (backend, enforces) and app/functions/rbac/permissions.ts (frontend, only hides buttons). Your role is a column in AppUsers; a role inside the token is ignored.

Frontend learns the role

AuthProvider → setMeOwner(uid) → GET /api/me → { role, usage }. Until it answers, status is loading and every useCan() is false.

Fails closed

If /api/me fails you become viewer and ServerNotice offers Retry. An unknown role string also becomes viewer.

UI gates

useCan(), <Can permission>, assertCan() in startScan, Admin link in MainNav. Admins change roles via PUT /api/admin/users/{id}/role.

10 · Where the app remembers you are logged in

In your browser, not on the server. The backend is stateless: no cookies, no sessions. Every request carries a token and is checked from scratch.

Your browser
survives refreshIndexedDB · firebaseLocalStorageDbWritten by the Firebase SDK (default "local" persistence). Holds the refresh token. This is the "remember me".
auto-renewedFirebase SDK · ID tokenA 1-hour JWT. getIdToken() hands it to apiFetch on every call.
memoryAuthProvider · CurrentUseruid, email, verified, role. Rebuilt on load by onAuthStateChanged.
memoryme-store · role + usageFrom GET /api/me.
memoryhistory-store · your scansFrom GET /api/scans (static mode: localStorage key projectmd.history.<uid>).
Backend
nothingNo sessionEach request: verify JWT signature with Google's public keys, then look up the role.
30 sIMemoryCache · role:uidSaves a DB hit per request. Evicted the moment an admin changes your role.
databaseAppUsers rowYour role and LastSeenAt. Created on your first GET /api/me.

See it yourself: DevTools → Application → IndexedDB → firebaseLocalStorageDb. Sign out deletes it.

11 · How animations are broken down

Three layers: measure in the browser, see with the vision model, package with plain code (no AI).

The estimate, in order

  1. AI's library hint says GSAP / ScrollTrigger → GSAP; says Framer → Framer Motion; says CSS → CSS
  2. Trigger is scroll-scrub, or the page has GSAP → GSAP
  3. Page has Framer → Framer Motion
  4. Trigger hover or loop → CSS, otherwise Framer Motion

Triggers: load, scroll, scroll-scrub, hover, click, loop, page-transition, unknown. Evidence is measured when it matches a browser-reported animation, otherwise inferred.

12 · How components and the design system are broken down

14 · Things I noticed while reading

  • appsettings.json ships Scanner:Mode = "static" (the backend mock). Real scans need Scanner__Mode=ai in backend/.env.
  • The Processing animation runs a fixed 3 s before the real request even starts, so every scan waits 3 s longer than it needs to.
  • frontend/lib/scrape.ts and test-scrape.ts are unused, import a playwright package that is not installed, and have no private-IP guard.
  • docs/HANDOFF.md has unresolved merge-conflict markers, and one side claims component previews no longer use AI. This branch still uses AI for them.
  • docs/ARCHITECTURE.md still describes the old browser-only mock.
  • The Results sidebar "thumbnail" is an illustration; screenshots are never stored.
